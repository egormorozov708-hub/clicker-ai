Сквозные тесты app.py на ONNX Runtime.

Среда: Windows, Python 3.14, ONNX Runtime 1.31.1, модель best.onnx (вход 640x640,
4 класса), режим --dry-run: клики не выполнялись, только логировались.
Тестовое окно: синтетическое полноэкранное окно ClickerTest с кадром игры.

1) Второй уровень, --upgrade-interval 3 --no-bonuses, ограничение 8 с:
   - модель стабильно находила game (1 рамка) и 4 кнопки improvement;
   - бот кликал по game и раз в 3 с покупал ровно одно улучшение, перебирая
     кнопки по очереди: «1/4», «2/4»;
   - итог: 42 кадра, 40 действий (game 38, improvement 2), 8.2 с.

2) Рекламный попап поверх игры, --no-improvements --no-bonuses, ограничение 7 с:
   - модель находила крестик advertising с уверенностью 0.95, фильтр app.py
     пропустил рамку;
   - пока реклама видна, кликов по game не было;
   - закрытие рекламы повторялось с кулдауном 3 с (в статичном тесте попап
     не исчезал);
   - итог: 38 кадров, 3 действия (только advertising), game 0, 7.1 с.

3) Остановка на Пробел (глобальный хоткей pynput, без превью):
   - бот запущен в режиме --dry-run с ограничением 30 с;
   - через 5 с отправлен Пробел;
   - процесс завершился в течение 6 с, в консоли появилось сообщение
     «Пробел — остановка.» и итоговая статистика;
   - итог: 27 кадров, 27 действий (game 27), 5.0 с.

4) Остановка на Пробел с включённым превью (Tkinter, OpenCV без GUI):
   - бот запущен с --preview --dry-run, ограничение 25 с;
   - через 5 с отправлен Пробел;
   - окно превью закрылось, процесс завершился в течение 7 с;
   - итог: 31 кадр, 31 действие (game 31), 5.2 с.

5) Скорость кликов по game (--dry-run, второй уровень, ограничение 3 с):
   - --click-burst 3 (по умолчанию): 19 кадров, 57 кликов game — около
     18 кликов/с;
   - --click-burst 1: 22 кадра, 22 клика game — около 7 кликов/с;
   - серия из трёх кликов на кадр ускоряет клики примерно в 2.6 раза.

6) Очередь улучшений со стабильными ID (юнит-тест buy_improvement):
   - 4 кнопки improvement, список детекций перед каждой покупкой перемешивался
     случайно;
   - бот нажал все 4 разные кнопки, повторов внутри круга не было;
   - после добавления пятой кнопки бот выбрал именно её, а не одну из уже
     нажатых;
   - после пятой покупки круг закончился и начался заново;
   - для бонусов аналогичная проверка: 2 из 2 кнопок без повторов;
   - проверка допуска stable_id/already_seen: сдвиг рамки на 3 px считается той
     же кнопкой, смещение на 300 px — новой.

7) Захват экрана и FPS (1920x1080, --dry-run):
   - mss.grab: около 32–35 мс, конвертация BGRA2BGR через cv2.cvtColor: ~1.7 мс;
   - pyautogui.screenshot: около 40–45 мс только на захват;
   - инференс ONNX: около 65–67 мс;
   - полный цикл без превью: 9.9–10.6 FPS (43 кадра за 4.1 с);
   - с Tkinter-превью: 5.7–7.8 FPS, ограничение — отрисовка окна превью.

8) Настраиваемая пауза после рекламы (--ad-settle 0.2 --ad-cooldown 0.5):
   - статичный кадр с попапом поверх игры, ограничение 3 с;
   - бот закрыл рекламу 6 раз, кликов по game не было;
   - пауза после закрытия соблюдалась, при уменьшении --ad-settle цикл
     ускоряется — значение вынесено в конфиг, а не захардкожено.

9) Диагностика --verbose:
   - прогон с --upgrade-interval 1 на втором уровне;
   - в логе появились причины отбраковки рамок по классам, например
     «отброшено game: правая колонка с рекламой x1»;
   - при 4 кнопках improvement бот последовательно нажал «1/4», «2/4», «3/4»,
     «4/4» — очередь не сбилась при обновлении кадра.

10) Закрытие окна OpenCV-превью и поиск окна (юнит-тесты):
   - при getWindowProperty < 1 Preview.show() возвращает -1 и помечает окно
     закрытым, главный цикл завершается;
   - find_window отсеивает свёрнутые окна, окна меньше 300x200 и несовпадения
     по заголовку;
   - load_class_names() находит classes.txt рядом с app.py и в _MEIPASS.

Все сценарии подтверждают: улучшения покупаются по одному с возвратом к game,
очередь устойчива к пересортировке и появлению новых кнопок, реклама имеет
приоритет и блокирует клики по игре, общий примитив click_box() используется
для всех действий, остановка на Пробел работает и без превью, и с окном превью,
а mss и настраиваемые паузы ускоряют цикл без роста нагрузки на модель.
